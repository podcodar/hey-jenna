# Nest — scaffolding with the Nest CLI

This project uses the Nest CLI (`@nestjs/cli`, already in `devDependencies`) as a scaffolding tool, but the generator's raw output **doesn't fully match** the project's convention — always adjust it after generating.

## How to generate

Always run this inside `server/` (the project's `nest-cli.json` lives there, with `sourceRoot: "src"`):

```bash
cd server
npx nest generate module <feature>
npx nest generate controller <feature> --no-spec   # or without --no-spec if you want the .spec.ts
npx nest generate service <feature>
```

For a full CRUD resource (generates module + controller + service + DTOs + entity at once):

```bash
cd server
npx nest generate resource <feature>
```

The generator will ask for the transport layer — choose **REST API** (the project uses `@nestjs/platform-express`, no GraphQL/microservices).

## Required adjustments after generating (project convention differs from the CLI default)

1. **DTOs**: `nest generate resource` creates a `dto/` subfolder with one file per DTO (`create-<feature>.dto.ts`, `update-<feature>.dto.ts`). In this project, consolidate everything into a single `src/<feature>/<feature>.dto.ts`, as in `users/users.dto.ts`. Delete the generated `dto/` subfolder and fix the imports in the controller/service.
2. **Entities**: the CLI generates a `<feature>.entity.ts` with an empty class. Since the project uses Prisma, the real entity type already comes from `generated/prisma` (e.g. `import { User } from 'generated/prisma'` in `users.controller.ts`). Delete the generated `.entity.ts` and use the Prisma Client type directly in return types (`Promise<Video[]>` etc).
3. **Providers in the module**: the generated `<feature>.module.ts` only lists `<Feature>Service`. Manually add any real dependency the service injects to the `providers` array — `PrismaService`, `AppLogger`, `SystemService` — following the pattern in `videos.module.ts`/`users.module.ts`. Without this, Nest fails at runtime with a DI error, not at build time.
4. **ValidationPipe**: add `@UsePipes(new ValidationPipe())` to the controller if it receives `@Body`/`@Query`/`@Param` validated by a DTO (the CLI doesn't add this on its own).
5. **Registering in AppModule**: add `<Feature>Module` to the `imports` array in `src/app.module.ts` — the generator sometimes already does this, confirm it.
6. **Logger**: if the service needs to log something, inject `AppLogger` (don't use `console.log` — forbidden by this project's ESLint config) and add `AppLogger` to the module's `providers`.

## After generating and adjusting

Always run, inside `server/`:

```bash
pnpm run lint
pnpm run test
```

If the feature uses Prisma and needs a new model, that is **not** generated by the Nest CLI — manually edit `server/prisma/schema.prisma` and run `npx prisma migrate dev --name <name>` + `npx prisma generate` (see the `review` skill and `AGENTS.md` for the migration rules).
